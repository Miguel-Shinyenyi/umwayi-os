section: CI (W47c, W47d), found while measuring tests/test_merge_main.py
title: The ui verify in merge_main runs once when no ui file changed, and twice when one did or the tool cannot tell
number: 318

`tests/test_merge_main.py` took about 860 s after W47c (1299 s before). Most of that was the ui verify, `python -m unittest tests.test_ui_package` (about 20 s), which `merge_main` ran twice in every run: once in its verify pass and once in the final pass that checks every file again.

After W47d the final pass skips a `python -m unittest tests.NAME` verify when no file of its path list changed since that verify last passed, and prints one line: `skipped the last verify of python -m unittest tests.test_ui_package: no file of its path list changed since it passed`.

- **The path list** is the one `tools/ci_map.json` already holds under `python` for `tests/NAME.py`. For the ui verify it is `.gitignore`, `ui` and `ui/dist`. The verify has no other list and none was made up. It is fixed in `verify_paths` in `tools/merge_main.py`.
- **Changed** means the content hash of any file under those paths differs between the moment just before the verify last ran and the final pass. A rewrite with the same bytes is no change; a file added, removed or edited is.
- **The verify still runs** (as before W47d) when a file of the list changed, when the tool cannot tell (no `ci_map.json` or no entry for that test, a file it cannot read, a file that is not a file, a folder or a link, an `OSError`), and for every verify that is not `python -m unittest tests.NAME` (for example `tools.ci_map check`, which has no path list).
- Not changed: the exit codes (0, 2, 3, 64), the first verify pass, the regenerate commands and the checks that a command wrote only listed files. A merge that regenerates `ui/dist` is verified once, after the build; the final pass skips it if nothing changed since.
- The seconds in `tools/ci_shards.json` are from CI reports and were not changed. The new time of `tests/test_merge_main.py` on CI is known only after a CI run.
- Still open: most of the time of the ui verify itself is its own regular expressions and the copies of the ui tree for each planted fault in `tests/test_ui_package.py`. Changing that file is the owner's decision.
